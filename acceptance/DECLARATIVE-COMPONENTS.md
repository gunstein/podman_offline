# Declarative components verification — 0.4.9

Backlog item 20. Baseline before changes: `a4fad83` on `main`, 253 product
tests (1 skipped) and 163 acceptance-harness tests passing with Python 3.13.16
and PyYAML 6.0.1. Historical reports keep their original evidence; nothing
below is a lab result.

## What changed

| Before | Now |
| --- | --- |
| `common.DEPENDENCIES`, `COMPONENTS`, `VERSION_FILES` fixed the graph | `bundles.yaml` declares it; `deployment/catalog.py` validates and compiles it |
| `bundle.yaml`: `name`, `components`, `requires` | One compiled descriptor: `name`, `version`, `requires`, `upgrade`, `public_from`, `routes`, `clients`, `accepts` |
| `dependencies/<id>.json` with ranges, written last | `metadata/<id>.json` with the descriptor, written before registrations; the `installed/<id>` marker is still last |
| platform/identity owners, `platform-routes`/`identity-clients`, app1/app2 client allowlist | Owners from `accepts`; registrations must belong to a known component |
| PUBLIC_ORIGIN/HTTPS_PORT required everywhere, PUBLIC_HOSTNAME only for `platform` | Required by placeholders or `public_from`; PUBLIC_HOSTNAME always derived and never set |
| client ID = component ID, base path = `/<id>` | client ID and base path are application settings; scopes stay `[openid, profile, <client id>]` |
| Images and the secret guard read every `components/*` directory | Only catalog components |
| `dev/dev.sh up` provisioned five demo components | Generic `dev/dev.sh`; demo provisioning in `dev/demo-credentials.sh` |
| `./deploy uninstall [platform]` | `./deploy uninstall [<component>]`, refused for another bundle's component |

No migration, alias or old-layout fallback was added. There are no existing
installations of the earlier metadata layout (review guide, section 1).

## Review follow-up

An independent review of `c00865f` found one regression from this change:
pending owner work could only be finished by a release declaring the same
roles (F6). Pending owners are now checked against the owners that installed
components and the bundle serve, so a release that drops its route still
completes the unfinished gateway work. Regressions:
`test_pending_owner_work_finishes_with_a_release_that_drops_the_role`, and
`test_lost_password_with_existing_renamed_volume_is_refused`, which checks the
exact renamed volume name. The sibling reinstall in `test_product_changes.py`
now uses the newly built bundle as its comment says.

The review's other findings are tracked in the backlog: F1, F3, F4 and F5 are
item 21, F2 and the suggested single effective-document pass were added to
item 21, and F7, F8 and F10 are item 25.
