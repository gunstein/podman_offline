# Credential path verification — 0.4.1

Baseline: `c6e828cc5cb528f44f64caf685f226ad5ac8f4bf` (separate platform and
Identity bundles). Before this change, 205 product tests and 158 acceptance-harness
tests passed with Python 3.12.14 / PyYAML 6.0.3.

## Scope and new paths

Fresh component state uses `credentials/` for passwords, session/API keys, private
keys and certificates, whether generated or externally supplied. Dev uses
`build/dev/<component>/credentials/`; production uses
`/var/lib/myproduct/<component>/credentials/`. Subdirectories and filenames are
retained:

| Component | Credential subdirectories |
| --- | --- |
| platform | `web/` |
| identity | `identity/`, `identity-db/`, `app/`, `users/` |
| app1 / app2 | `database/`, `todo/` |
| help | No required credential files |

Updated component defaults, `GENERATED_SECRETS`, `SECRET_FILES`, `VOLUME_FILES`,
public client certificate descriptors, certificate generation, dev smoke paths,
acceptance transfers/database checks/persistence observations, standalone bundle
fixture directory, examples, ignore rules and active operator documentation.
Shared `PKI/private` and CA material stay in place.

`GENERATED_SECRETS` still selects files generated by deploy. `SECRET_FILES` and
`VOLUME_FILES` still select delivery to containers. Database preflight resolves
the declared password path and refuses missing passwords with existing data
volumes. Database/session/API generation remains in deploy; the component
certificate script does not generate database passwords or session keys.
Existing valid files are preserved on repeated generation/install.

No Pod/Secret/PVC names, keys, mounts, DB identities, OIDC IDs/scopes/URLs,
connection-string runtime mechanism, config precedence, application code,
manifests or immutable image tags changed. Release metadata (`VERSION`,
`PLATFORM_VERSION`, `IDENTITY_VERSION`) advances to 0.4.1 for the changed host-side
bundles. This does not require rebuilding unchanged application images.

Bundle checks retain declaration-based protection for generated secrets at
arbitrary paths. They also reject copying component/standalone/dev credential
directories or files, including resolved symlink aliases, so externally supplied
private keys are protected even when absent from `GENERATED_SECRETS`. The
existing checksums, private modes, offline image policy, SELinux and fapolicyd
flows remain in place.

No migration, move procedure, alias, automatic old-path discovery or fallback was
added. Tests use isolated fresh state. No existing credentials or database volumes
were moved, regenerated or deleted. Production config remains authoritative and
is not rewritten from new defaults.

## Local verification

Final local results: 207 product tests and 158 acceptance-harness tests passed
with Python 3.12.14 / PyYAML 6.0.3. Ruff lint/format, pyright, vermin (Python 3.6
minimum) and shellcheck passed; `git diff --check` is clean.

Existing tests now exercise new paths for generation/delivery, retained bytes,
private modes, empty/invalid secrets, missing database passwords with retained
volumes, registration, server/client password consistency, unsafe output and
symlink paths, render/import contents and checksums. Two focused product
regressions cover all five real component defaults during dev/production
initialization, and direct/aliased externally delivered private credentials in
the bundle guard and actual archive-building flow. The acceptance credential
transfer test asserts the exact new paths while keeping private bytes out of logs.

`git diff` confirms no changes to component manifests or application sources:
container mounts, resource names and image tags are byte-for-byte unchanged.
The harness executes guest Python snippets and tests orchestration with transport
stubbed; it is not a real container or target-machine run.
